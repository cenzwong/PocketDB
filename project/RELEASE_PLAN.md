# Release plan

| Release | Demonstration | Compatibility and test gate | Documents and limitations |
| --- | --- | --- | --- |
| Feasibility baseline (M0) | Repeat the two-device probe; run hosted PGlite and reload persisted data; exercise native prototypes. | Record browser, device, network and static host matrix with observed limitations and fallback outcomes. | Experiment instructions, ADRs, initial scope and updated estimates. |
| Local preview (M1) | Start either engine, run a database operation and verify normal reload of a persistent instance. | Contract tests, worker integration and supported browser smoke checks for both engines. | Local quick start, storage mode, quota and lifecycle notes. |
| Peer-access preview (M2) | Host a key-value instance on a static build, join from a second physical device, perform a write/read and show a PostgreSQL parameterized query. | SDK and protocol tests, identity and authorization checks, and two-device evidence including network and signalling details. | Invitation flow, SDK examples, errors and dependency disclosures. |
| Hackathon release (M3) | Two laptops use the deployed Pages site to start and share both P0 engines, execute remote reads/writes, use the SDK, inspect activity, reload and export. | CI lint/type/unit/integration/build gates, supported browser matrix, real deployment, failure and security review, documentation examples and measurements against provisional §28 targets. | Quick start, executable examples, protocol, security, persistence, architecture, supported browsers, self-hosting, extension guides and troubleshooting. Explain hosted availability, storage durability and relay limits. |
| Native release (M4) | Start both local bridges from the CLI and run a PostgreSQL driver and Redis client against browser-owned data. | Supported Node and driver versions, transaction and command subset, loopback defaults, disconnect cleanup and artifact installation. | CLI and Python examples, driver compatibility matrix and exclusions. Gate public package publication on approval. |
| Distributed release (M5) | Multiple authorized independent replicas edit offline, reconnect and converge, with ongoing persistence. | Membership, duplicate/out-of-order updates, state import/merge, quotas and supported browser compatibility. | Replication examples and semantics, including offline access and retention boundaries. |
| Selected engines (M6) | Run a reproducible workload on each selected adapter. | Engine-specific contract, format round-trip and static browser tests. | Capability matrix, examples and supported browser/storage constraints. |
| Agent release (M7) | An approved agent connects or provisions through the supported surface, discovers capabilities and performs authorized operations. | SDK/MCP compatibility, permission enforcement, secret handling and structured errors. | Executable agent example and supported data operations, provisioning and credential setup. |

Hosted release regressions include host suspension or close, malformed/oversize messages, expired or revoked credentials, read-only writes, duplicated requests, uncertain mutation outcomes, storage quota, worker termination and interrupted transactions. Capture exact commands, versions, devices and outcomes in the [milestone tickets](MILESTONES.md). Compare performance to the [handoff's provisional targets](../docs/handoff.md) after establishing a reference environment. Maintain a versioned compatibility matrix for browsers and native drivers as they ship.
