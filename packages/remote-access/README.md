# Remote access session host

`@pocketdb/remote-access` joins an already authenticated peer connection to `DatabaseRuntime`. The caller supplies an authorization callback that revalidates the connection-bound `AuthenticatedPeerSession` before every message. This keeps invitation parsing and peer authentication in `@pocketdb/protocol`, engine lifecycle in `@pocketdb/runtime`, and bytes/connection lifecycle in `@pocketdb/transport`.

The host handles protocol negotiation, exposes only the invited engine's capabilities, echoes heartbeat pings, opens and closes connection-owned sessions, and routes requests with correlated responses or structured errors. Requested instance, engine and access must match the authenticated invitation. Disconnect closes the peer's open sessions.

Request IDs are deduplicated per connection. Reusing an ID with identical content returns the prior result; reusing it with different content is rejected. The default per-peer bounds are 256 KiB per inbound message, 256 KiB per encoded operation response, 16 open engine sessions, 64 active requests, 120 new requests per fixed 60-second window, and 256 retained completed request results. Effective inbound and outbound caps are the minimum of the configured limit, the transport's advertised `maxMessageBytes`, and the protocol's 256 KiB ceiling. The default WebRTC transport advertises a 16 KiB message cap. `maxRequestBytes` and `maxResultBytes` can lower the effective cap. Completed duplicate retries use their cached result and do not consume rate budget.

Limit failures have structured outcomes: an oversized request returns `request-too-large` with `not-started` and closes that peer connection; session, active-request and rate limits return `session-limit-reached`, `request-limit-reached` or `request-rate-limit` with `not-started`. An operation that completes but cannot fit in the configured response budget returns `result-too-large` with `unknown`, because a mutation may already have taken effect. The host does not replay it. A timeout after dispatch returns `request-timeout` with `unknown`, aborts where supported, and never replays the mutation. A completed engine error is `failed`; a rejected or unauthorized request is `not-started`.

The default execution deadline is 30 seconds. `AbortSignal` is cooperative: the key-value adapter checks cancellation before applying an operation; PGlite checks before starting serialized work, but an in-flight SQL call does not expose a verified cancellation primitive. `WorkerEngineAdapter` terminates its worker if its own request watchdog expires, releasing worker-owned execution and sessions; a caller timeout can therefore leave the database worker alive until that watchdog fires. A timed-out mutation remains `unknown` even if worker cleanup later completes. Closing a PGlite session or stopping its instance rolls back an open transaction; forced worker termination cannot run that orderly cleanup, so rollback of an in-flight transaction on forced termination is not claimed. Connection-wide authentication limits belong to `PeerSessionAuthority`, which defaults to 256 pending challenges and 1,000 authenticated peer sessions per authority; these limits apply to peers sharing that authority. The remote session and request limits above apply separately to each authenticated peer connection.

This package does not perform signaling, ICE configuration or the authentication challenge exchange. The caller establishes the authenticated session and supplies the connection-bound authorization callback before creating the host.
